# Provenance and scope

## Frozen audit samples

- `annotation_sample_bird.csv` contains 100 BIRD value-linking instances selected by
  the project's E6 label-noise/audit driver. Each row carries the database identifier,
  question, available evidence, table, column, deterministic gold literal, and
  deterministic drift flag needed for the human protocol check.
- `annotation_sample_icd.csv` contains 100 constructed ICD records selected by the same
  E6 audit workflow. Each row carries the record code and description, deterministic
  Wikidata QID/code target, and constructed drift type.
- The corresponding A/B worksheets were initialized as exact copies of the frozen
  samples with blank annotation columns. The package validator ensures their row order
  and frozen fields remain identical to the source samples.

The source experiment driver is not needed to perform or score this frozen audit. The
two CSV snapshots in this folder are the authoritative inputs for this annotation pass.

## Offline context (added 2026-09-10)

The first release of this package showed each BIRD row only as a database name,
question, evidence sentence, and the single `table.column` chosen by the protocol, and
each ICD row only with the frozen Wikidata reference. That was insufficient for a human
to check two parts of the protocol offline: whether the literal was attributed to the
right table (several BIRD tables share column names such as `nationality`, `language`,
`name`, `Diagnosis`) and whether a record code is a real ICD-10-CM code. Both judgments
had required outside knowledge. The package now ships:

- `bird_schema.csv` / `bird_schema.md`: all 798 declared columns of the 11 BIRD dev
  databases in the sample, from BIRD's `dev_tables.json` (dev_20240627).
- Context columns in the BIRD sample and worksheets: `question_id`, `gold_sql`,
  `sql_tables`, `sql_column_ref`, `sql_column_table` (alias- and scope-resolved table
  that the query actually filters), `same_name_columns` (every same-named column in the
  schema with a present/absent flag for the literal), `matching_cell_values`, and
  `column_distinct_count`, all computed from the BIRD dev SQLite databases.
- `bird_column_values.csv`: per row, the matching raw cell values and a sample of up to
  60 other distinct values of the protocol column.
- Context columns in the ICD sample and worksheets: `record_code_in_icd10cm`,
  `record_code_icd10cm_desc`, `record_category_code`, `record_category_title`,
  `nearest_valid_icd10cm`, `node_wikidata_icd9_claim`, `node_all_icd10_codes`,
  `n_valid_codes_under_node`,
  computed from the artifact's ICD-10-CM code table (`data/icd_kg/icd10.csv`) and the
  Wikidata ICD-9/ICD-10 query snapshot (`data/icd_kg/wikidata_icd9_icd10.json`).
- `icd_icd10cm_reference.csv`: every valid ICD-10-CM code under each protocol node's
  code(s), with descriptions. The KG keeps one entry per (node, ICD-10 code) and the
  protocol reports the node's last-listed code as `protocol_gold_code`, so for nodes
  with several codes the record may descend from another of them; the reference covers
  all of them.

All of it is generated by `build_offline_context.py`, which rebuilds the 200 items from
the driver's seeds (shuffle seed 0, sample seed 1) and asserts equality with the frozen
samples before writing. The original frozen fields, the annotator entries already
recorded, the adjudication lists, and the statistics in `agreement.json` were unchanged
by this addition (checked by re-running `compute_agreement.py`). A first annotation
pass had been entered without this context and relied on outside knowledge of the BIRD
schemas and ICD-10-CM codes; it was discarded and all four worksheets were reset to
blank on 2026-09-10 so that the recorded audit is the one performed from the package
alone. That new pass is now complete: both annotators completed all 200 assigned rows,
and the 17 protocol challenges were jointly adjudicated.

## Offline Wikidata reference

`icd_wikidata_reference.csv` was retrieved from the official Wikidata `wbgetentities`
API on `2026-09-10T07:11:58+00:00`. It covers the 99 unique QIDs referenced by the 100
ICD audit rows and stores English labels, descriptions, aliases, current P494 (ICD-10)
claim values, last revision IDs, modification timestamps, source URLs, and retrieval
time. Each row therefore identifies the exact source revision observed when the package
was assembled.

The optional `refresh_wikidata_reference.py` command documents and reproduces this
retrieval using only Python's standard library. Refreshing is maintenance, not part of
the offline annotation workflow. Wikidata structured data are provided under CC0; see
<https://www.wikidata.org/wiki/Wikidata:Licensing>.

## Claim boundary

The benchmark labels are deterministic, but the manuscript may report agreement on the
independent human audit of whether those protocols were applied correctly. Blank or
partially completed worksheets are not evidence of agreement. Results from this
package may be added to the paper only after:

1. both annotators independently complete all 200 assigned rows;
2. `compute_agreement.py` reports 100 paired rows for both datasets;
3. every generated adjudication row is resolved; and
4. reported numbers are copied from the final `agreement.json` without alteration.

All four conditions are satisfied in the current package. `agreement.json` records
`complete` for both datasets, 12/12 BIRD and 5/5 ICD adjudication rows resolved, BIRD
adjudicated gold/drift error rates of 0.12/0.00, and ICD adjudicated gold/drift-type
error rates of 0.00/0.05. Its workflow status prevents a blank or incomplete audit from
being interpreted as a zero-error result.
